# پلتفرم تخفیف و کش‌بک (Coupon & Cashback Affiliate Marketplace)

نسخه کامل‌شده — آماده برای پیاده‌سازی با Claude Code و آپلود روی هاست cPanel، دوزبانه انگلیسی/آلمانی، با طراحی حرفه‌ای.

## ۱. ایده در یک جمله

مارکت‌پلیس تخفیفی که کدها و آفرهای فروشگاه‌های مختلف را جمع‌آوری می‌کند؛ کاربر از طریق لینک اختصاصی سایت شما به فروشگاه می‌رود و خرید می‌کند، شما از فروشگاه (مرچنت) کمیسیون افیلیت می‌گیرید و بخشی از آن را به‌عنوان کش‌بک به کاربر برمی‌گردانید. مدل مشابه Honey، RetailMeNot و Rakuten.

## ۲. تصمیم فنی مهم: سازگاری با هاست cPanel

چون قرار است روی هاست اشتراکی/cPanel آپلود شود، باید استکی انتخاب شود که با هاست‌های معمولی (بدون دسترسی root، بدون سرویس Node دائمی تضمین‌شده) کار کند:

**پیشنهاد اصلی: Laravel (PHP) + MySQL.** اکثر هاست‌های cPanel از PHP و MySQL به‌صورت پیش‌فرض پشتیبانی می‌کنند، دیپلوی با آپلود فایل یا Git ساده است، و Laravel فریم‌ورکی بالغ با ابزارهای آماده برای احراز هویت، صف کار (queue)، ارسال ایمیل، و ادمین پنل است.

**فرانت‌اند:** Blade + Livewire (یا Alpine.js برای تعامل سبک) در همان پروژه Laravel — این باعث می‌شود همه‌چیز یک پروژه PHP واحد باشد و نیازی به Node.js در سرور تولید نباشد (فقط برای build کردن CSS/JS در زمان توسعه از Vite استفاده می‌شود که خروجی استاتیک تولید می‌کند).

**اگر هاست شما cPanel با پشتیبانی Node.js Selector دارد** (بسیاری از هاست‌های جدید دارند)، گزینه دوم Next.js + Node API است، اما پیچیدگی دیپلوی (پروسه دائمی Node، PM2، پورت) بیشتر است. **توصیه من Laravel است مگر مطمئن باشید هاستتان Node.js App را به‌خوبی پشتیبانی می‌کند.**

**دیتابیس:** MySQL (استاندارد در cPanel).

**صف و کرون:** استفاده از Laravel Queue (database driver، نیازی به Redis نیست) و Cron Job هاست برای اجرای `php artisan schedule:run` هر دقیقه (تنظیم می‌شود از بخش Cron Jobs در cPanel).

**ایمیل:** از طریق SMTP هاست یا سرویس‌هایی مثل Mailgun/SendGrid (چون بسیاری هاست‌های اشتراکی محدودیت ارسال ایمیل دارند).

## ۳. دوزبانگی (انگلیسی/آلمانی)

Laravel به‌صورت بومی از فایل‌های ترجمه (`lang/en`, `lang/de`) پشتیبانی می‌کند. نکات طراحی:

سوییچر زبان در هدر (پرچم یا کد EN/DE)، پیش‌فرض بر اساس Accept-Language مرورگر یا انتخاب کاربر که در کوکی/سشن ذخیره می‌شود. مسیرها با پیشوند زبان باشند برای سئو: `example.com/en/store/nike` و `example.com/de/store/nike` (نه فقط تغییر کوکی بدون تغییر URL — گوگل باید بتواند هر دو نسخه را جدا ایندکس کند).

محتوای دیتابیسی (نام فروشگاه، عنوان آفر، توضیحات) باید چندزبانه ذخیره شود — یا با ستون‌های جدا (`title_en`, `title_de`) یا جدول ترجمه جدا (`offer_translations`). برای این پروژه با توجه به تعداد محدود زبان (۲ زبان)، ستون‌های جدا ساده‌تر و کافی است.

پنل ادمین هم باید امکان وارد کردن نسخه انگلیسی و آلمانی هر فروشگاه/آفر را همزمان بدهد (دو تب یا دو فیلد کنار هم).

فرمت اعداد، ارز و تاریخ باید بر اساس زبان/منطقه تغییر کند (کتابخانه `laravel-lang` یا carbon locale).

## ۴. طراحی حرفه‌ای — جهت‌گیری بصری

چون گفتید دیزاین باید حرفه‌ای باشد، این معیارها را برای Claude Code مشخص کنید تا خروجی generic و آماتور نشود:

سیستم طراحی مشخص (رنگ اصلی برند + رنگ ثانویه برای کش‌بک/تخفیف، معمولاً سبز یا نارنجی برای حس "پول برگشتی")، تایپوگرافی با فونت وب مدرن (Inter, Manrope یا مشابه، + فونت آلمانی که کاراکترهای Ö/Ü/ß درست رندر کند)، کارت‌های فروشگاه/آفر با سایه ملایم و hover effect، حالت تاریک/روشن (Dark mode) اختیاری، ریسپانسیو کامل موبایل‌فرست (اکثر ترافیک کوپن از موبایل است)، آیکون‌های یکدست (Lucide یا Heroicons)، اسکلتون لودینگ (Skeleton loading) به‌جای اسپینر ساده برای حس مدرن‌تر، انیمیشن‌های ظریف با Alpine.js/CSS transition (نه افراطی).

از فریم‌ورک Tailwind CSS استفاده کنید — با Laravel هماهنگی خوبی دارد و برای ساخت سریع UI حرفه‌ای بدون نوشتن CSS خام مناسب است.

## ۵. مدل درآمدی و جریان پول

سه مدل کمیسیون: **CPS** (درصدی از خرید نهایی، رایج‌ترین)، **CPA** (مبلغ ثابت به ازای ثبت‌نام/اولین اقدام)، **CPL** (مبلغ ثابت به ازای لید معتبر). فروشگاه به شما کمیسیون می‌دهد، شما بخشی (مثلاً ۵۰-۷۰٪) را کش‌بک به کاربر برمی‌گردانید و بقیه سود پلتفرم است.

## ۶. مکانیزم ردیابی

**کوکی + لینک افیلیت اختصاصی:** کلیک کاربر روی «مشاهده آفر» یک رکورد کلیک (کاربر، فروشگاه، زمان، IP، device) ثبت می‌کند و بعد ریدایرکت 302 به لینک افیلیت فروشگاه انجام می‌شود.

**Postback/S2S:** فروشگاه یا شبکه افیلیت وقتی خرید تایید شد، webhook با `click_id` به سرور شما می‌زند — دقیق‌ترین روش، باید یک API endpoint امن (`POST /api/postback`) برایش بسازید.

**کد اختصاصی برای فروشگاه‌های بدون API:** هر کاربر کد یکتا می‌گیرد، فروشگاه گزارش استفاده را دستی یا با فایل اعلام می‌کند و ادمین در پنل تطبیق می‌دهد.

نکته: چون شبکه افیلیت استاندارد ایرانی محدود است، برای بازار انگلیسی/آلمانی (که ظاهراً هدف اصلی شماست با توجه به دوزبانگی) شبکه‌های بین‌المللی مثل Awin، CJ Affiliate، Impact، یا Rakuten Advertising گزینه اصلی اتصال به فروشگاه‌ها خواهند بود — این‌ها API و postback استاندارد دارند و اتصال به آن‌ها راحت‌تر از قرارداد مستقیم تک‌تک فروشگاه‌هاست، به‌خصوص در فاز اول.

## ۷. ساختار سایت — سمت کاربر

**صفحه اصلی:** دسته‌بندی فروشگاه‌ها، آفرهای ویژه/پرطرفدار، بنر کمپین‌های فصلی، جستجوی فروشگاه/برند، سوییچر زبان.

**صفحه فروشگاه:** لوگو، توضیح، لیست کدها/آفرهای فعال، درصد کش‌بک، دکمه «دریافت کد»/«فعال‌سازی آفر» (ثبت کلیک + ریدایرکت)، نظرات و امتیاز کاربران، تاریخ انقضا و شرایط.

**صفحه جزئیات کد:** کد کپی‌شدنی، دستورالعمل، مدت اعتبار، حداقل مبلغ خرید، محدودیت‌ها.

**پروفایل کاربر:** موجودی کش‌بک (در انتظار/تایید‌شده/قابل برداشت)، تاریخچه کلیک و خرید، درخواست تسویه (کیف پول/PayPal/کارت بانکی — برای بازار آلمان PayPal و SEPA transfer اولویت دارند)، لیست علاقه‌مندی‌ها، تنظیمات اعلان.

**اطلاع‌رسانی:** ایمیل برای آفر جدید، هشدار انقضای کد، تایید کش‌بک — با قالب دوزبانه بر اساس زبان انتخابی کاربر.

**افزونه مرورگر (فاز دوم):** اعمال خودکار بهترین کد هنگام بازدید از سایت فروشگاه — افزایش چشمگیر تبدیل و نگهداشت.

**برنامه ارجاع:** کاربر با دعوت دوستان کش‌بک اضافه می‌گیرد.

**بلاگ/راهنمای خرید:** محتوای SEO دوزبانه برای بهتر دیده‌شدن در گوگل انگلیسی و آلمانی.

## ۸. پنل ادمین — فیچرهای کامل

**داشبورد:** KPI لحظه‌ای (کلیک، نرخ تبدیل، درآمد کمیسیون ماه جاری، کش‌بک پرداختی، سود خالص)، نمودار روند، لیست فروشگاه‌های پردرآمد.

**مدیریت فروشگاه‌ها:** افزودن/ویرایش، نرخ کمیسیون و درصد کش‌بک هر فروشگاه، وضعیت فعال/غیرفعال، اطلاعات API/شبکه افیلیت، دسته‌بندی، لوگو/بنر — همه فیلدها با نسخه EN و DE.

**فرم «افزودن فروشگاه/آفر جدید» (بخش درخواستی شما):** فرم مستقل که هم فروشگاه تازه و هم اولین آفرش را می‌سازد.

فیلدهای فروشگاه: نام (EN/DE)، لوگو، دسته‌بندی، توضیح کوتاه (EN/DE)، لینک سایت اصلی، لینک افیلیت یا وضعیت «در انتظار قرارداد».
فیلدهای آفر: عنوان (EN/DE)، نوع آفر (کد تخفیف / لینک مستقیم / کش‌بک درصدی)، کد تخفیف، درصد یا مبلغ تخفیف، درصد کمیسیون دریافتی از فروشگاه، درصد کش‌بک به کاربر، تاریخ شروع/پایان، حداقل مبلغ خرید و محدودیت‌ها.
وضعیت انتشار: پیش‌نویس / منتظر تایید / منتشرشده، با امکان زمان‌بندی خودکار انتشار (تاریخ شروع = تاریخ نمایش در سایت).
گزینه «ویژه/پین‌شده» برای نمایش در بالای صفحه اصلی یا بخش «تازه‌ها».
پیش‌نمایش زنده کارت آفر قبل از انتشار.

از نظر فنی: ثبت فرم یک رکورد Merchant (اگر جدید است) و یک رکورد Offer می‌سازد؛ صفحه اصلی آفرها را زنده از دیتابیس می‌خواند (کوئری با کش کوتاه‌مدت، نه صفحه استاتیک)، پس با زدن «انتشار» بلافاصله و بدون نیاز به دیپلوی مجدد در صفحه اصلی هر دو زبان ظاهر می‌شود.

**مدیریت کدها/آفرها:** ویرایش/انقضای دستی، زمان‌بندی خودکار، تایید کدهای پیشنهادی کاربران، گزارش «کار نمی‌کند» و بازبینی، اولویت نمایش.

**مدیریت تراکنش‌ها و کمیسیون:** لیست کلیک‌ها با وضعیت (pending/approved/rejected/paid)، ثبت دستی برای فروشگاه‌های بدون API، بازبینی fraud، گزارش تطبیق با صورتحساب فروشگاه/شبکه افیلیت.

**مدیریت کاربران:** لیست، موجودی کیف پول، تاریخچه فعالیت، مسدودسازی در صورت تقلب، سطح‌بندی VIP.

**مدیریت تسویه (Payouts):** صف درخواست برداشت، تایید دستی/خودکار زیر سقف مشخص، اتصال به PayPal/SEPA/کیف پول، تاریخچه پرداخت، حداقل مبلغ برداشت.

**مدیریت محتوا:** بلاگ دوزبانه، صفحات استاتیک (درباره ما، قوانین، حریم خصوصی — برای بازار آلمان رعایت GDPR الزامی است)، بنرها و کمپین‌های فصلی، اعلان‌های ایمیل.

**گزارش‌گیری:** درآمد به تفکیک فروشگاه/دسته/بازه/زبان کاربر، خروجی Excel/CSV، قیف تبدیل، نرخ ریزش.

**تشخیص تقلب:** فیلتر کلیک تکراری از IP/device مشابه، تشخیص self-referral، الگوی مشکوک کش‌بک، لاگ کامل برای هر ادعای پرداخت.

**مدیریت نقش‌ها (RBAC):** ادمین کل، مدیر محتوا، مدیر مالی، پشتیبانی.

**تنظیمات سیستم:** ارز پیش‌فرض هر زبان (EUR برای DE)، مدت اعتبار کوکی ردیابی، API key شبکه‌های افیلیت، تنظیمات SEO سراسری هر زبان، تنظیمات GDPR (بنر رضایت کوکی، فرم درخواست حذف داده کاربر — الزامی برای مخاطب آلمانی).

## ۹. الزامات قانونی مهم برای بازار آلمان (GDPR)

چون سایت به آلمانی هم هست و احتمالاً مخاطب اروپایی دارد، باید از ابتدا رعایت شود: بنر رضایت کوکی (Cookie Consent) قبل از هر ردیابی، صفحه Impressum (الزام قانونی آلمان برای هر سایت تجاری — اطلاعات مالک سایت)، صفحه Datenschutzerklärung (سیاست حریم خصوصی به آلمانی)، امکان درخواست کاربر برای دانلود/حذف داده‌های شخصی‌اش (حق فراموش‌شدن).

## ۱۰. معماری فنی (نسخه Laravel/cPanel)

**ساختار پروژه:** یک اپلیکیشن Laravel واحد شامل بخش عمومی (Public — چندزبانه)، بخش پنل ادمین (`/admin`، محافظت‌شده با میدلور احراز هویت و نقش)، و API داخلی برای Livewire/Ajax.

**جداول اصلی دیتابیس:** `users`، `merchants` (با ستون‌های `_en`/`_de`)، `offers`/`coupons` (با ستون‌های `_en`/`_de`، `status`: draft/pending/published، `published_at`)، `categories`، `clicks` (با `click_id` یکتا، `user_id`، `merchant_id`، `ip`، `created_at`)، `conversions` (لینک‌شده به `click_id`، مبلغ خرید، کمیسیون، وضعیت تایید)، `wallet_transactions`، `payout_requests`، `reviews`.

**ریدایرکت سرویس:** روت سبک مثل `GET /go/{merchant_slug}` که کلیک را لاگ می‌کند، کوکی/سشن ست می‌کند، و ریدایرکت 302 به لینک افیلیت انجام می‌دهد — باید سریع باشد و از کوئری سنگین در این مسیر پرهیز شود.

**دیپلوی روی cPanel:** ساخت پروژه لوکال با Composer/Artisan → build کردن asset با `npm run build` (فقط در محیط توسعه، خروجی در `public/build`) → آپلود کل پروژه با Git Deploy (اگر cPanel از Git پشتیبانی می‌کند) یا FTP/File Manager → تنظیم Document Root روی پوشه `public/` (مهم‌ترین نکته امنیتی — باید فقط پوشه public در دسترس عمومی باشد، نه ریشه پروژه) → تنظیم `.env` با اطلاعات دیتابیس MySQL هاست → اجرای مایگریشن‌ها از طریق SSH (اگر هاست SSH دارد) یا اسکریپت مایگریشن یک‌بار‌مصرف در صورت نبود SSH → تنظیم Cron Job برای Laravel Scheduler.

## ۱۱. فازبندی راه‌اندازی

**فاز اول (MVP):** سایت اصلی دوزبانه با لیست دستی فروشگاه/کد، فرم افزودن فروشگاه/آفر در پنل ادمین (همان بخش درخواستی)، ثبت کلیک ساده، پنل ادمین پایه (داشبورد، مدیریت آفر، مدیریت کاربر)، اتصال به ۱-۲ شبکه افیلیت بین‌المللی (Awin یا Impact) برای شروع.

**فاز دوم:** کیف پول و تسویه کاربران، Postback خودکار، پیشنهاد کد توسط کاربران، رعایت کامل GDPR.

**فاز سوم:** افزونه مرورگر، اپ موبایل، برنامه ارجاع، تشخیص تقلب پیشرفته، سطح‌بندی VIP.

## ۱۲. چالش‌های کلیدی

جذب فروشگاه اول کار سخت‌ترین بخش است — با اتصال به شبکه‌های افیلیت بین‌المللی (که صدها فروشگاه از قبل در آن‌ها هستند) این مشکل در فاز اول حل می‌شود، به‌جای مذاکره مستقیم با تک‌تک فروشگاه‌ها. کدهای منقضی که هنوز نمایش داده می‌شوند اعتماد کاربر را از بین می‌برند، پس سیستم گزارش و بازبینی خودکار باید از فاز اول جدی گرفته شود. تاخیر تایید کمیسیون (معمولاً ۳۰-۹۰ روز به‌خاطر دوره بازگشت کالا) باید در UI به‌وضوح به‌عنوان وضعیت «در انتظار تایید» نشان داده شود.

## دوزبانگی (اجباری، از پایه پروژه)
- دو زبان: انگلیسی (en) و آلمانی (de)
- استفاده از سیستم ترجمه بومی لاراول (lang/en, lang/de) برای متن‌های ثابت رابط کاربری
- مسیرها با پیشوند زبان برای سئو: /en/... و /de/...
- محتوای دیتابیسی (نام فروشگاه، عنوان/توضیح آفر) با ستون‌های جدا: title_en, title_de,
  description_en, description_de و مشابه برای همه مدل‌های عمومی
- سوییچر زبان در هدر که مسیر فعلی را با پیشوند زبان دیگر باز می‌کند
- تنظیم locale بر اساس پیشوند URL، با fallback به Accept-Language مرورگر برای بازدید اول
- ارز پیش‌فرض برای نسخه آلمانی: EUR

## طراحی (اجباری — باید حرفه‌ای باشد، نه جنریک)
- سیستم طراحی مشخص: رنگ اصلی برند + رنگ ثانویه سبز/نارنجی برای نشان‌دادن کش‌بک/تخفیف

- آیکون از کتابخانه Heroicons یا Lucide
- کامپوننت‌های Blade قابل استفاده مجدد (کارت آفر، بج کش‌بک، دکمه CTA، badge وضعیت)

## مدل داده اصلی (اسکیمای مایگریشن مورد نیاز)
- users: احراز هویت استاندارد لاراول + wallet_balance, locale_preference, role
- merchants: name_en, name_de, slug, logo, category_id, description_en, description_de,
  website_url, affiliate_link, commission_rate, cashback_rate, api_provider, api_credentials
  (رمزنگاری‌شده), status (active/inactive)
- categories: name_en, name_de, slug, icon
- offers: merchant_id, title_en, title_de, description_en, description_de, type
  (coupon_code/direct_link/cashback_percent), coupon_code, discount_value, min_purchase_amount,
  starts_at, expires_at, status (draft/pending/published), is_featured, published_at
- clicks: click_id (UUID یکتا), user_id (nullable برای مهمان), merchant_id, offer_id, ip_address,
  user_agent, created_at
- conversions: click_id (foreign key), order_amount, commission_amount, cashback_amount,
  status (pending/approved/rejected/paid), confirmed_at
- wallet_transactions: user_id, type (earned/withdrawn/adjusted), amount, related_conversion_id
- payout_requests: user_id, amount, method (paypal/bank_transfer/sepa), status, requested_at,
  processed_at
- reviews: user_id, merchant_id یا offer_id, rating, comment, status

## بخش عمومی سایت (Public)
1. صفحه اصلی: هیرو + دسته‌بندی‌ها + آفرهای ویژه + آفرهای تازه، همه از دیتابیس زنده خوانده شود
2. صفحه لیست فروشگاه‌ها با فیلتر دسته‌بندی و جستجو
3. صفحه فروشگاه: اطلاعات فروشگاه + لیست آفرهای فعال آن + نظرات
4. دکمه "دریافت کد"/"فعال‌سازی آفر" که یک روت GET /go/{merchant_slug}?offer={id} صدا می‌زند،
   کلیک را در جدول clicks ثبت می‌کند و با ریدایرکت 302 کاربر را به affiliate_link می‌فرستد
5. صفحات احراز هویت (ثبت‌نام/ورود/فراموشی رمز) با Laravel Breeze یا Fortify
6. پروفایل کاربر: موجودی کیف پول، تاریخچه کلیک/تراکنش، فرم درخواست تسویه، علاقه‌مندی‌ها
7. صفحات استاتیک اجباری برای بازار آلمان: Impressum, Datenschutzerklärung (Privacy Policy),
   Terms of Service — هر دو به EN و DE
8. بنر رضایت کوکی (Cookie Consent) قبل از هر ردیابی/آنالیتیکس

## پنل ادمین (/admin، محافظت‌شده با میدلور نقش)
1. داشبورد با KPI: تعداد کلیک، نرخ تبدیل، درآمد کمیسیون ماه جاری، کش‌بک پرداختی، سود خالص
   (query aggregate روی جداول clicks/conversions)
2. CRUD کامل فروشگاه‌ها با فیلدهای EN/DE
3. **فرم "افزودن فروشگاه و آفر جدید" — این مهم‌ترین بخش پنل ادمین است:**
   یک فرم واحد (می‌تواند چند مرحله‌ای/wizard باشد) که همزمان یک رکورد merchant (اگر جدید است،
   یا انتخاب فروشگاه موجود) و یک رکورد offer می‌سازد. باید شامل تمام فیلدهای بالا در دو زبان
   باشد، دکمه "ذخیره پیش‌نویس" و دکمه "انتشار فوری"، و یک تب پیش‌نمایش زنده که نشان می‌دهد
   کارت آفر در صفحه اصلی چه شکلی خواهد بود. بعد از انتشار (published_at ست می‌شود و
   status=published)، آفر باید فوراً و بدون نیاز به کش پاک‌کردن دستی در صفحه اصلی هر دو
   زبان ظاهر شود — یعنی کوئری صفحه اصلی باید status=published AND published_at <= now()
   را زنده چک کند، نه از کش طولانی‌مدت استفاده کند.
4. CRUD کدها/آفرها با زمان‌بندی publish/expire خودکار (از طریق Laravel Scheduler)
5. مدیریت تراکنش‌ها: لیست clicks و conversions با فیلتر وضعیت، امکان تایید/رد دستی
6. مدیریت کاربران و کیف پول
7. صف درخواست‌های تسویه با تایید/رد
8. مدیریت نقش‌ها (ادمین کل/مدیر محتوا/مدیر مالی/پشتیبانی) با Laravel Gate/Policy
9. گزارش‌گیری با خروجی CSV
10. تنظیمات سیستم (نرخ‌های پیش‌فرض، API key شبکه‌های افیلیت)
